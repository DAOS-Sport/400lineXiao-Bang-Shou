> 用途：供人工審閱、修整邏輯使用

---

## 一、整體流程圖

```
LINE 群組訊息
    ↓
[路由層] routes.ts:1224
    ↓ setImmediate（非同步，不阻塞主流程）
[進入點] ingestMessageForAnnouncement()
    ↓
身份判斷（主管？VIP？重點群組？）
    ↓
預篩 preFilterMessage()
  ├── VIP → 全跳過，直接送 GPT
  ├── 有關鍵字 → 通過
  ├── 主管 + 字數≥30 → 通過
  ├── 重點群組 + 字數≥15 → 通過
  └── 否 → 丟棄，不進 DB
    ↓
GPT 分類 classifyAnnouncement()
  └── 模型：GPT-4o-mini，timeout 20秒
    ↓
信心過濾
  ├── VIP → 全跳過，全存
  └── 非VIP：candidateType=ignore + confidence<0.4 → 丟棄
    ↓
寫入 announcement_candidates 表
  ├── status = 'pending_review'  （有效公告）
  ├── status = 'vip_chat'        （VIP 的閒聊）
  └── status = 'ignored'         （低信心 ignore，目前已被上游過濾）
```

## 三、預篩邏輯（announcementPreFilterService.ts）

> 目的：在送 GPT 之前先用規則過濾，降低 API 費用。VIP 用戶直接跳過此步驟。

### 觸發關鍵字（任一符合即通過，不受字數限制）

| 分類 | 關鍵字 |
|------|-------|
| **規則型 (rule)** | 即日起、請統一、不得、禁止、務必、一律、通知大家、規定、SOP、請各位、從今以後、請注意、特此通知、依規定、不可以、嚴禁、需要統一、請確認、提醒大家、統一 |
| **活動型 (campaign)** | 活動、優惠、折扣、期間、報名、特價、贈送、限時、限量、招生、免費、體驗、開放、推廣 |
| **話術型 (script)** | 統一說法、客人若問、請這樣回覆、回覆方式、話術、請勿這樣回、遇到客人、客戶問、可以這樣說、請回答、標準說詞、禁止說詞 |
| **通知型 (notice)** | 公告、通知、注意事項、請知悉、請轉知、最新消息、異動、調整、更新、改變、變更、修正 |

### 升級 scope 關鍵字

若訊息包含以下字樣，`scopeType` 自動升級為 `multi_facility`：
`全館、所有館別、全公司、統一規定、全部適用、各館、總公司、全體員工、全員`

### 字數門檻（無關鍵字時）

| 身份 | 門檻 |
|------|------|
| 主管（DB 管理員 or 職稱含主管關鍵字） | ≥30 字 |
| 重點群組一般成員 | ≥15 字 |
| 非重點群組一般成員 | ❌ 不通過（丟棄） |

### 主管職稱判斷（displayName 含以下字樣）

`主任、主管、館長、組長、督導、總監、經理、副理、主席、前台主管、服務台`

## 四、GPT 分類邏輯（announcementClassifierService.ts）

### 模型設定

| 項目 | 值 |
|------|---|
| 模型 | `gpt-4o-mini` |
| Temperature | 0.1（低隨機性，穩定輸出） |
| Max tokens | 800 |
| Response format | JSON object |
| Timeout | 20 秒 |

### 分類類型（candidateType）

| 類型 | 說明 |
|------|------|
| `rule` | 規定、禁止、SOP、流程要求 |
| `notice` | 公告、通知、消息異動 |
| `campaign` | 活動、招生、期間方案 |
| `discount` | 優惠、折扣、特價 |
| `script` | 統一說法、話術、回覆標準 |
| `ignore` | 閒聊、抱怨、模糊討論 |

### Scope 類型（scopeType）

| 類型 | 說明 |
|------|------|
| `group` | 僅限該群組 |
| `facility` | 整個場館 |
| `multi_facility` | 多館適用 |
| `global` | 全公司 |

### 輸出欄位

```json
{
  "candidateType": "rule | notice | campaign | discount | script | ignore",
  "scopeType": "group | facility | multi_facility | global",
  "title": "公告標題（自動生成）",
  "summary": "摘要說明",
  "recommendedAction": "建議動作（可為 null）",
  "badExample": "禁止說法（可為 null）",
  "recommendedReply": "建議回覆（可為 null）",
  "appliesToRoles": ["frontdesk", "lifeguard", "admin", "supervisor", "new_staff"],
  "startAt": "ISO datetime（可為 null）",
  "endAt": "ISO datetime（可為 null）",
  "confidence": 0.0,
  "reasoningTags": ["標籤陣列"]
}
```

## 五、狀態流程

```
ingest 完成後寫入 DB，status 值如下：

pending_review ─ 有效公告（等待人工審核）
vip_chat       ─ VIP 的閒聊訊息（不是公告，但保留供查閱）
ignored        ─ 低信心的 ignore（目前幾乎不會出現，上游已過濾）
approved       ─ 人工核准（前端審核頁面操作）
rejected       ─ 人工駁回（前端審核頁面操作）
```

## 六、排除條件（不送進 ingest）

以下訊息**在路由層直接排除**：

| 條件 | 說明 |
|------|------|
| 訊息類型不是 `text` | 圖片、貼圖、位置等一律排除 |
| 來源不是 `group` | 個人私訊排除 |
| 文字 `< 4 字` | 太短直接略過（在 ingest 函式內） |
| 以 `@小幫手` 開頭 | AI 客服指令，排除 |
| 以 `交辦` 開頭 | 任務交辦指令，排除 |
