# 公告篩選機制（5 層管線）

> 版本：2026-05
> 對應檔案：`server/services/announcement/`、`server/prompts/announcementClassifier.ts`

---

## 🏗️ 整體流程圖

```
LINE 訊息進來
    │
    ├─ Webhook 過濾：只收「群組裡的純文字」
    │   （圖片/影片/貼圖/語音/檔案/位置 / 1對1 私訊全部不進）
    │
    ▼
┌──────────────────────────────────────────────┐
│ Layer 0    硬排除（hardExclude）              │ ← 純規則，免費
│ Layer 0.5  公告重要性預分類                    │ ← 純規則，免費
│ Layer 1    規則評分（scoreMessage）            │ ← 純規則，免費
│ Layer 2    三段式決策（makeDecision）          │ ← 純規則，免費
│ Layer 3    AI 分類（Gemini 2.5 Flash Lite）   │ ← 只有「灰區」才送 AI
│ Layer 4    寫入 DB（含 24h 去重）              │
└──────────────────────────────────────────────┘
    │
    ▼
announcement_candidates 表 → 等管理員審核 → 發布
```

## 🛡️ Layer 0：硬排除（一秒丟掉）

**檔案**：`server/services/announcement/announcementRuleEngine.ts`

| 條件 | 直接排除原因 |
|---|---|
| 字數 < 4 | `too_short` |
| 開頭 `@小幫手` | `ai_command` |
| 開頭 `交辦` | `task_command`（這是任務系統的工作） |
| 完全等於這些短回覆 | `short_reply`：「收到/好/ok/已知悉/哈哈/好的/嗯/了解/謝謝/好啊/曉得/知道了/👍/😊/🙏/辛苦了/早安/午安/晚安」 |
| 4~6 字且含噪音詞 | `short_noise`（噪音詞：哈哈/笑死/辛苦了/收到/好的/ok/OK/了解/已知悉/晚安/早安/午安/謝謝/已/好啊/嗯/喔/XD/哈） |
| 完全沒有中文/英文字（純 emoji 或符號） | `no_cjk_content` |

## 🚦 Layer 0.5：重要性預分類

**檔案**：`server/services/announcement/announcementImportanceClassifier.ts`

### 🚫 直接排除（NOT_ANNOUNCEMENT）— 三類「看起來像公告但其實不是」

| 類別 | Regex 範例 |
|---|---|
| **個人任務** | `^幫我...` / `^你(去\|幫\|等一下\|來)` /「小美你等一下去...」/「請XX去處理...」 |
| **交接事項** |「鑰匙放在抽屜...」/「已完成/處理/確認/交接/繳交/送出」/「記得接著/繼續/接手」/「早班/晚班記得...」 |
| **異常/事故** |「有人被/受傷/跌倒/昏倒/溺水/出事」/「會員...受傷/抱怨」/「設備...壞/故障/異常」/「壞掉/壞了」/「虎頭蜂」/「緊急情況」 |

### ⭐ 重要公告訊號（MUST_READ）— 命中 ≥2 個或 1 個 + 字數 ≥ 30

| 訊號代碼 | Regex |
|---|---|
| `IMMEDIATE_EFFECT` |「即日起」 |
| `MULTI_FACILITY_SCOPE` |「各館/全館/所有館別/全體員工/全體同仁」 |
| `UNIFORM_RULE` |「統一使用/說法/流程/做法/規定」 |
| `REQUEST_COMPLIANCE` |「請大家...確認/配合/遵守/知悉」「請各...配合/確認」 |
| `OPERATION_CLOSURE` |「暫停開放/休館/封閉/停課/停班」 |
| `SYSTEM_MAINTENANCE` |「系統維護/升級/更新/異動」 |
| `CONSTRUCTION_GUIDANCE` |「施工...引導/改走/注意/配合」 |
| `MANDATORY_KEYWORDS` |「一律/禁止/不得/務必」 |
| `SOP_CHANGE` |「SOP/流程異動/作業流程」 |
| `DEADLINE` |「截止/期限」+ 含數字 |

### 📋 一般公告（NORMAL）— 含這些詞且字數 ≥ 15

報名、課程、活動資訊、通知、更新、招生、優惠、夏令營、冬令營、開放、體驗課、公告

## 📊 Layer 1：規則評分

**檔案**：`announcementRuleEngine.ts` → `scoreMessage()`

### 加分維度

| 維度 | 關鍵字（部分） | 每命中 1 個加分 |
|---|---|---|
| **強關鍵字** | 即日起、一律、禁止、不得、務必、SOP、請統一、統一說法、禁止說詞、請各館配合、全體員工、休館、暫停開放、恢復營運、課程取消、時段調整、價格調整、請轉知、請知悉、異動如下、公告如下 | **+10** |
| **弱關鍵字** | 活動、優惠、折扣、通知、調整、更新、修正、報名、開放、推廣、招生、體驗、限時、限量 | **+2** |
| **時間詞** | 今天、明天、本週、即日起、截止、開始、結束、延後、提前、暫停、恢復 | **+3** |
| **對象詞** | 櫃台、救生員、同仁、員工、各館、全體員工、客人、會員、主管、前台、行政 | **+3** |
| **行動詞** | 請、需、務必、記得、統一、改為、停止、恢復、配合、確認、轉知、回覆、說明、不可、不要 | **+2** |
| **結構訊號** | 含「：\n」「規定如下」「注意事項」「以下說明」等多句式 | **+5**（一次） |
| **跨館 scope** | 含「全館/各館/所有館別/全公司/統一規定/全部適用/全員/全體員工」 | **+8**（一次） |

### 扣分維度

| 維度 | 扣分 |
|---|---|
| **噪音詞** | 同上「噪音詞」清單，每命中 1 個 **−4** |

## ⚖️ Layer 2：三段式決策

**檔案**：`announcementRuleEngine.ts` → `makeDecision()`

依序檢查，命中就停：

| 條件 | 結果 | 說明 |
|---|---|---|
| 命中強關鍵字 ≥1 個 | **rule_matched** | 直接寫入候選池，**不送 AI**（省錢） |
| 三元素（時間+對象+行動）命中 ≥2 項 **且** 總分 ≥ 12 | **rule_matched** | 直接寫入 |
| 總分達門檻 **且** 至少有強關鍵字或一項元素命中 | **rule_matched** | A 級群組門檻 14 / B 級 18 / C 級 25 |
| 主管 + 字數 ≥ 40 + 總分 ≥ 8 | **needs_ai_review** | 送 Gemini 判斷 |
| **VIP**（陳柏榮）+ 條件達標 + 總分 ≥ 8 | **rule_matched** | 半白名單 |
| **VIP** + 條件達標但分數不夠 | **needs_ai_review** | 送 Gemini 判斷 |
| **VIP** 條件不達 | **drop** | 直接丟棄 |
| 一般成員 + 字數達門檻（A:25 / B:35 / C:∞）+ 總分 ≥ 6 | **needs_ai_review** | 送 Gemini 判斷 |
| 其餘 | **drop** | 丟棄 |

### 群組分級（決定門檻嚴格度）

| Tier | 群組 | 評分門檻 | 一般成員字數門檻 |
|---|---|---|---|
| **A**（最寬鬆） | 7 個工作群（新北高中/三重商工/三民/松山/竹科泳池/竹科戶外/三蘆櫃台） | 14 | 25 字 |
| **B**（中等） | 三民排班、原授權群 | 18 | 35 字 |
| **C**（最嚴格，只接受強規則） | 駿斯 IT 技術群 | 25 | ∞（不靠字數放行） |

### VIP 半白名單（陳柏榮 `U8fd0e4...`）

即使非主管，VIP 訊息只要符合：

- 字數 ≥ 25，**或**
- 含強關鍵字，**或**
- 同時有時間+對象，**或**
- 同時有對象+行動

→ 才會進入後續判斷（避免 VIP 閒聊也被當公告）

## 🤖 Layer 3：AI 分類（Gemini 判讀）

**檔案**：`announcementClassifierService.ts` + `prompts/announcementClassifier.ts`

只有 Layer 2 判定為 **`needs_ai_review`** 的灰區訊息才會送，且必須先過 **Pass 1 gate**：

- 是主管？→ 過
- 字數 ≥ 20？→ 過
- 含這些詞之一？→ 過：公告、規定、統一、提醒、注意、請各位、從今天起、即日起、暫停、恢復、異動、報名、活動、優惠、折扣、不可、禁止、必須、一律、請改成、請不要、請改說、SOP、流程、新規定

過了才會打 Gemini API。Gemini 會回傳：

| 輸出欄位 | 說明 |
|---|---|
| `candidateType` | rule / notice / campaign / discount / script / **ignore**（最後一道防線） |
| `scopeType` | group / facility / multi_facility / global |
| `title` | ≤ 20 字標題 |
| `summary` | ≤ 80 字白話摘要 |
| `confidence` | 0~1 |
| `appliesToRoles` | frontdesk / lifeguard / admin / supervisor / new_staff |
| `startAt` / `endAt` | ISO8601 時間 |
| `recommendedAction` | 一句話祈使語氣（給值班人員看） |
| `recommendedReply` | 對客話術（≤ 60 字，可直接照念） |
| `badExample` |「不要這樣說/做」反例 |
| `extractedJson` | 5W1H：who/what/when/where/thing/originalQuote |
| `priority` | must_read / high / normal / low |

### priority 自動規則

- `rule` + 主管 + scope ≥ facility → **must_read**
- `notice` + 7 天內到期 → **high**
- `script` 類 → 永遠 ≥ **high**
- 其他 → **normal**

### 模型與成本

- 預設模型：`gemini-2.5-flash-lite`
- 成本約 OpenAI GPT-4o-mini 的 2/3（每千次 ~NT$8 vs ~NT$11）
- 可用 `ANNOUNCEMENT_CLASSIFIER_MODEL` 環境變數切換到 `gemini-2.5-flash` / `gemini-2.0-flash` / `gemini-2.0-flash-lite`

---

## 💾 Layer 4：寫入 + 24 小時去重

**檔案**：`server/services/candidateDedup.ts`

- 計算 `contentHash = sha256(title + summary + groupId + date)`
- 24 小時內同 hash 不重複寫入
- 如果命中：升級已存在那筆的 `confidence`（取較高者）

## 📋 一張圖看懂篩選嚴格度

```
1000 則訊息進來
    │
    ├─ ~50%  Layer 0 硬排除（短回覆/表情/無內容）
    │
    ├─ ~30%  Layer 0.5 排除（任務/交接/異常/閒聊）
    │
    ├─ ~15%  Layer 2 drop（分數不夠 / 字數不夠 / 非主管/VIP）
    │
    ├─ ~3%   Layer 2 rule_matched（強關鍵字直接過 → 寫入，不花錢）
    │
    └─ ~2%   Layer 3 送 Gemini（灰區，每筆 ~NT$0.008）
                │
                └─ Gemini 回 ignore 的還會再丟掉
```

**真正寫入候選池的大概是進來訊息的 3~5%**，這也是為什麼這幾個月 prod 收了 1400+ 則訊息，candidates 表卻很少 — 不是壞掉，是嚴格設計使然。

## 🎛️ 可調整的地方（不用改 code）

| 想做的事 | 怎麼做 |
|---|---|
| 換 AI 模型 | Secrets 加 `ANNOUNCEMENT_CLASSIFIER_MODEL=gemini-2.0-flash-lite`（更便宜） |
| 加新主管 | 改 `SUPERVISOR_USER_IDS` env var，或進 `users` 表 set role=supervisor |
| 加新 VIP | 改 `announcementConfig.ts` 的 `VIP_USERS` |
| 把某群組降級不要那麼多公告 | 改 `GROUP_TIER_MAP` 從 A 改 B 或 C |
| 加新強關鍵字 | 改 `announcementRuleEngine.ts` 的 `STRONG_KEYWORDS` |
| 加新「不要當公告」規則 | 改 `announcementImportanceClassifier.ts` 的 `NOT_ANNOUNCEMENT_RULES` |
