## 一、目標

我要的不是訓練模型，也不是抓很多訊息。
我要的是：

1. **大幅降低 GPT token 成本**
2. **只讓真正重要、可進值班首頁、可影響前線值班行為的訊息進入審核池**
3. **把公告流和任務流切乾淨**
4. **保留人工審核，不做全自動正式發布**
5. **讓未來可直接接員工值班首頁 / facility home / 已讀確認**

請把這套邏輯做成 production-ready，不要只改 prompt，要真的改成完整可維護的 pipeline。

## 二、現況問題（請直接修掉）

目前系統問題如下：

- VIP 使用者目前全抓、全跳過預篩、直接送 GPT，太浪費 token

## 三、這次修改的總原則

### 核心原則
- **Precision > Recall**
- **規則先行，AI 最後**
- **先過濾再分類，不是先分類再過濾**
- **只有灰區訊息才送 GPT**
- **能用 deterministic rule 決定的，就不要花 token**
- **預設不腦補**
- **不確定就不要進 pending_review**
- **scope 預設是 group，只有明確跨館語意才升級**
- **公告必須能回答：這會不會影響今天值班、回覆客人、場館作業、交接或活動執行？**

### 商用標準
- 可配置
- 可統計
- 可測試
- 可擴充
- 可查錯
- 可審核
- 不阻塞 webhook 主流程
- AI 失敗不影響主流程

### Layer 0：硬排除（Hard Exclusion）
以下直接排除，不進公告流程：

- 非 `text`
- 非 `group`
- 文字長度 < 4
- 以 `@小幫手` 開頭

### Layer 2：三段式決策（不進 AI / 直進待審 / 才送 AI）

請把訊息分成三類：

#### 1. `drop`
直接丟棄，不寫入公告候選
適用於：
- 純雜訊
- 純聊天
- 純情緒
- 單一弱關鍵字但沒有時間/對象/行動
- 太短且無公告結構

#### 2. `rule_matched`
規則足夠明確，不送 GPT，直接寫入待審核池
適用於：
- 強關鍵字命中
- 或「時間 + 對象 + 行動」三元素至少命中兩項且內容明確
- 或明確屬於 rule / script / notice / discount / campaign 其中一種
- 或主管明確下達統一規範 / 異動 / 對客說法
- 或包含休館、課程取消、價格調整、標準回覆等高價值公告

#### 3. `needs_ai_review`
規則無法完全判定，但疑似重要，才送 GPT
適用於：
- 主管長文但不夠明確
- 重點群組較長內容
- 疑似通知但語意模糊
- 跨句描述的異動資訊
- 可能有價值，但 rule engine 不夠確定

## 六、群組與身分分級

### 1. 重點群組不要再全部同級
請建立 group tier config：

- `A`：高營運相關群組（值班、櫃台、場館營運）
- `B`：中度相關群組
- `C`：低優先或觀察群組（例如 IT 討論群）

預設策略：
- A：可較寬鬆
- B：中等
- C：非常保守，原則上只有強規則命中或主管明確公告才進

### 2. 任務群與公告群分離
任務提醒白名單群組不等於公告重點群組。
請不要共用同一套判斷規則。
請保留未來可拆出 task pipeline 的結構。

### 3. VIP 改成「半白名單」
VIP 不可再全抓全送 GPT。

#### VIP 規則改為：
VIP 訊息只有在以下任一條件成立才進公告流程：
- 長度 >= 25
- 命中強關鍵字
- 命中「時間 + 對象」
- 命中「對象 + 行動」
- 含明確公告結構（例如規定、異動、價格、課程、休館、統一說法）

否則：
- 不送 GPT
- 可選擇存成 `vip_raw`
- 或直接略過，不進 announcement_candidates
